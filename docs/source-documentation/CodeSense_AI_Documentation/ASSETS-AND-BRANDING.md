# Brand, Logo, Icons and Asset Requirements

## 1. Identity

Product name: **CodeSense AI**. Descriptor: **AI-Powered Code Review and Bug Detection Platform**. Brand should communicate clarity, engineering confidence, learning and careful analysis. It must not imply official VS Code/Microsoft ownership or affiliation.

## 2. Logo direction

Create an original, scalable symbol combining source/code with inspection, clarity or analysis. Do not copy VS Code icon, Monaco branding or another protected mark. Wordmark remains legible at navigation size. Provide horizontal/compact, monochrome/accent and vector variants, plus favicon sizes.

## 3. Icons

Use one consistent icon family and stroke/fill weight. Icons have semantic meaning. Decorative icons can be hidden from assistive technology; icon-only controls require accessible names. Avoid emoji as production UI iconography. Pair status color with text/icon.

## 4. Asset quality

Prefer original vector assets and optimized licensed fonts. Avoid unrelated stock photos in the editor workspace. Keep any marketing illustration restrained. Do not use placeholder screenshots, invented UI screenshots or fabricated customer logos. Do not include assets without verified license/permission.

## 5. Asset pipeline

Record source, author/provider, license, modification and format. Optimize SVG/raster assets. Remove private metadata. Use versioned asset paths when appropriate. Verify every referenced asset exists and loads in production.

## 6. Favicon and metadata

Provide crisp favicon/application metadata and original icon with contrast at small sizes. Page title/share image must be accurate. No fabricated review count, customer proof or unsupported claims.

## 7. Review checklist

Check logo on dark/light backgrounds, small-size legibility, contrast, spacing, favicon, icon alignment, responsive header, asset loading and license records. Keep identity distinct from third-party developer tools.
